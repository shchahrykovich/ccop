# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

ccop is a macOS menu bar app that shows all Claude Code sessions on this Mac and their token usage, to help reduce it. It is a Rust workspace (core library and CLI) with a Swift menu bar app.

## Commands

```
cargo test --workspace                                   # all Rust tests
cargo test -p ccop-core the_newest_line                  # one Rust test (name filter)
cargo clippy --workspace --all-targets                   # expected: no warnings
swift test --package-path apps/menubar                   # Swift tests
swift test --package-path apps/menubar --filter SessionListTests
scripts/build-app.sh                                     # "build/CCOP Dev.app", ad-hoc signed (local build)
scripts/build-app.sh --developer-id                      # build/CCOP.app, signed with Developer ID + hardened runtime
scripts/install.sh --user --launch                       # build and install "CCOP Dev.app" to ~/Applications
scripts/publish.sh [--patch|--minor|--major|--set X.Y.Z] # notarized DMG as a GitHub release (needs .env.notarize)
"build/CCOP Dev.app/Contents/MacOS/CCOP" --show                # run with the popover open (for screenshots)
"build/CCOP Dev.app/Contents/MacOS/CCOP" --window <id-prefix> anatomy   # open the window at a session (id prefix) and tab
cargo run -p ccop -- sessions --since 1d --verbose       # the CLI; --verbose prints files, MB read, ms
cargo run -p ccop -- anatomy <id-prefix>                 # turns, lanes, tools of one session (--json for the app)
cargo run -p ccop -- usage --days 7                      # tokens and API-equivalent cost per day (--json: per hour)
cargo run -p ccop -- chat <id-prefix> --lane main --json # full texts of one lane, by event index (the app's Chat tab)
cargo run -p ccop -- call <id-prefix> <tool_use_id>      # one tool call in full: input and whole output (--max-bytes cuts it)
cargo run -p ccop -- guide                               # the instructions for agents (libs/core/src/guide.md)
cargo run -p ccop -- brief <id-prefix>                   # short report on one session; with no id: --since 7d --project x
cargo run -p ccop -- top commands --since 7d --by time   # a list: commands, causes, agents, sessions, turns, errors, projects, tips
cargo run -p ccop -- cause <id-prefix> Bash --limit 20   # the costliest calls of a tool or a program
cargo run -p ccop -- time <id-prefix>                    # where the clock went: model, tools, subagents, waiting
cargo run -p ccop -- context <id-prefix> --call 147      # what fills one call's context, by file and command (--each: by item)
"build/CCOP Dev.app/Contents/MacOS/CCOP" --plan                # open the plan settings window at launch
"build/CCOP Dev.app/Contents/MacOS/CCOP" --about               # open the About panel at launch
UPDATE_EXAMPLES=1 cargo test -p ccop-core --test api_example   # rewrite api/anatomy.example.json after a type change
```

To screenshot the window while another app is in front, capture it by window number (`screencapture -l <number>`; get the number from `CGWindowListCopyWindowInfo` for owner `CCOP`) instead of bringing it to the front.

Use a separate index so a test run does not touch the app's: `CCOP_CACHE_DIR=<tmp dir> cargo run -p ccop -- sessions`.

## Architecture

```
~/.claude/projects/**/*.jsonl ──► ccop CLI (Rust) ──► ~/Library/Caches/ccop/index.json
                                     │
                                     ├─ ccop sessions --json ──► CCOP.app (Swift): popover + main window
~/.claude/projects/<f>/<id>.jsonl ──┐  │
  <id>/subagents/agent-*.jsonl      ├──┴─ ccop anatomy <id> --json ──► Anatomy and Context tabs (read on demand, no index)
  <id>/subagents/agent-*.meta.json ─┘
```

- `libs/core` (`ccop-core`): no file access. `transcript.rs` turns lines of one transcript file into a `Transcript` (title, folder, branch, prompts, times, tokens by model). `Transcript` is serializable so the CLI can save it and feed more lines later. `session.rs` joins a main transcript with its subagent files into a `Session`, the JSON type the app reads. `anatomy.rs`: `LaneReader` turns one file (main or one subagent) into a `Lane` of events (prompt, answer, tool, compact, error); `build` links each subagent to the `Agent` tool call that started it and splits the main lane into turns. `context.rs` splits each call's context size into parts (see below); the parts are sums of `context_items` (one per prompt, tool result, answer's output, summary, Start, Other, with the first and last call that held it), so the Context tab and `ccop context` can list what one call holds. `spend.rs` puts the API-equivalent cost of each model call on what made it run (the tool results before it, split evenly; a prompt; a subagent's task) and writes tips with a cost or a saving; it is the `spend` field of the anatomy JSON. The late-compaction tip (`replay`) plays each lane again with an auto-compact window of 200K, 300K and 400K and names the one that saves the most: each extra compaction pays a summary call and a cache write of the short context (start context + 30K), and later calls read less. It needs a saving of 5% of the session, because an agent that stops soon after the window loses money. A Bash call that Claude Code refused in a worktree session gets a `Refusal` kind (loop, stdin, variable, xargs, git, complex, other) from the refusal text and the command; the error tip gives a count and a fix for each kind.
- `apps/cli` (`ccop`): `index.rs` finds the files and keeps the index: per file the size, inode, mtime, the byte offset after the last whole line, and the `Transcript` state at that offset. A run reads only appended bytes; a file that got shorter or has a new inode is read from 0; a half-written last line waits for the next run. Files are read by up to 8 threads. Bump `FORMAT` in `index.rs` when `Transcript` or `Entry` changes meaning, so old indexes are dropped.
- `apps/menubar`: Swift package. `CCOPKit` has the Swift copy of `Session`, the CLI runner, filters, day sections, formatting and the resume command (all tested). `CCOP` is the AppKit app: no Dock icon (`LSUIElement`), left click opens the popover, right click shows the menu (Open Window, Plan Settings, Refresh, Check for Updates, Quit). It runs the CLI every 30 s while the popover is open and every 2 min otherwise. The period filter starts at Today and the folder filter at all folders; the last choice of each is saved (`Period.load`, `FolderScope.load`). The menu bar number is the tokens of sessions active today (whole-session totals, not only today's tokens).
- Chat tab (`ChatView.swift`): the messages of one lane as in the chat. The texts come from `ccop chat` (`LaneReader::with_chat`, keyed by event index); the tokens and `cost_micros` of each event come from the anatomy. `CallSheet` (`CallViews.swift`) shows one call in full via `ccop call`; the Spend tab's Bash table opens it from each program's list of calls (`CommandGroup.items`). `AppModel.openInChat` goes to one event (`ChatPlace`): `ChatView` takes `chatTarget`, clears a filter that hides the row, opens a tool row and scrolls to it. The call sheet and the Context tab's side panels have a Go to Chat button.
- Opening a window: `raiseOverOtherApps()`, then `NSApp.activate()`. `activate()` is only a request, so with `makeKeyAndOrderFront` the window of a background app can open behind the front app. Check with `open -g -n "build/CCOP Dev.app" --args --plan` and `CGWindowListCopyWindowInfo`.
- The window's tab does not change while the user is on it: `AppModel.windowShown` and `windowAnatomy` are copies, taken when the user comes to a tab or a session (`showLatestInWindow`). A refresh changes only the list and the header; `windowHasUpdates` and `windowUpdateCount` (new model calls and prompts, `Format.changes`, at most 4 characters) drive the refresh icon in the header, and its click reads the new data with the old data still shown. They are copies because the popover loads into `anatomies`. `.loaded`'s date is when the read started, so a change during a read counts as new. A click on the chosen session in the list goes to its Overview (`chooseInWindow`).
- Chat tab: `FoldedText` cuts a prompt or a lead's task at 5 lines as drawn (a line that wraps counts as several), by comparing the heights of two hidden copies; other messages are not cut.
- Table sort: `TableSort` (CCOPKit) and `SortTitle`: the first click on a column sorts down, the second up, the third restores the table's order. Used by Subagents, Your messages and Bash commands. A column's width must include `SortTitle.arrowRoom`. `hoverRow()` tints the row under the mouse.
- Flags: `SessionFlags` (CCOPKit) saves the flagged session ids in the app's defaults (`flaggedSessions`), so a dev build and a release have separate flags and the CLI does not see them. `Period.flagged` is the list: `SessionList.filter` shows the flagged sessions of any age, also a closed one with 0 tokens, which other lists hide. `SessionMenu` is the right-click menu of a list row; `FlagButton` is in the popover's session header and the window's header.
- Overview: `CompactionTable` lists every compaction of the session, in any lane, from `Anatomy.compactionRows` (CCOPKit); it is hidden when there are none. Before and After are what the `compact_boundary` record says; Next call is the context the lane's next model call read, which also counts the system prompt and the tools. The Subagents table has a Compactions column, and the Average context card counts the compactions of all lanes, while its average and max are of the main lane.
- Table rows (Bash programs, Bash calls, Subagents, Compactions, Largest additions): `rowMenu` in `RowMenu.swift` adds the right-click menu View, Go to Chat, Copy as JSON, Export as JSON. The JSON is one row (`RowExport`), with the CLI's snake_case keys; a tool call has its whole input and output from `ccop call`. A row must be one view for the menu to cover its whole width, so these tables use an `HStack` with measured column widths, not a `Grid`.
- Back and Forward in the window's header (⌘[ and ⌘]): `WindowHistory` (CCOPKit) keeps `WindowPlace`s: the session and tab, and only what that tab shows (the Chat tab's lane and event, the Cause tab's cause). `AppModel.noteWindowPlace` records a step from the `didSet` of those values, after the click's code ends, so a click that sets several values is one step; showing a place from the history adds no step, because that place is already current. A new value in the window that should be a step must call it too. Scroll positions, Chat filters and open sheets are not steps.
- Context tab charts: `ChartPick` keeps a value chosen with a click, so the pointer can reach the side panel; a click on it lets it go. Both side panels always have the same height (fixed rows for the lanes, every part of the lane also at 0), so the page below does not move.
- The main window (`MainWindow.swift`): the session list beside Overview, Spend (`SpendView.swift`: tips, cost per prompt, per cause, per agent), Cause (`CauseView.swift`: one cause and each call behind it, from `Cause.items`, which `analyze_with_paid` in `spend.rs` writes; the chips are in groups by MCP server, from `Spend.causeGroups` and `ToolName` in CCOPKit; a "By cause" row in Spend and a tool card in Anatomy open it), Anatomy (`AnatomyView.swift`: Canvas timeline, turns, tools, subagents) and Context (`ContextView.swift`: Swift Charts stacked area; on top `TokenTimelineView.swift`: the session's tokens over time as bars, the biggest period marked, from `Consumption` in CCOPKit). While it is open the activation policy is `.regular` (Dock icon); on close it goes back to `.accessory`. `TimeScale` (CCOPKit) shortens idle gaps over 2 min on the timeline.
- Plan and limits: `libs/core/src/pricing.rs` prices each call at API rates (model, 1-hour vs 5-minute cache writes, Haiku 5.5's long-prompt rate card) in micro-dollars; `Transcript.hours` keeps tokens and cost per Unix hour, so days and weeks can be cut at any reset time. `CCOPKit/Plan.swift`: `PlanSettings` (a reset moment repeating every 7 days, the weekly limit in dollars), `Plan.status` (week, calendar days, daily share = limit / 7), `Plan.calibrate` (limit = cost since reset ÷ the weekly percent). `CCOPKit/Limits.swift`: `LimitsReader` runs `claude -p --no-session-persistence /usage` (home folder, 90 s timeout; without the flag each read leaves a "/usage" session with 0 tokens). It tries a login shell, then a login and interactive shell (a login shell does not read `.zshrc`), then the installers' folders; a path chosen in Plan settings (`claudePath` default) replaces that search. `UsageLimits.parse` reads its text: `Current week (all models): 97% used · resets Nov 3 at 7:59pm (Europe/London)`, one line per limit, then Claude Code's own tips per period. It is plain text, not a stable format (checked 2026-11-03); it makes no model call (the saved sessions had 0 tokens). `AppModel` reads it at launch and every hour; `Plan.applying` then sets the reset from it and the limit from ccop's cost since that reset ÷ the percent (only at 5% or more: /usage rounds to whole percents). Typing the numbers by hand stays as a fallback in Plan settings. The popover has a graph under the two cards (`WeekCompareCard`, `Plan.comparison`): the running total of this week and of the week before, from each week's reset. It has two modes: from the reset to now (`WeekComparison.soFar`, the default), or the whole limit week; the choice is saved (`weekGraphSoFar`). The menu bar shows `33%/87%`: today as a percent of today's allowance (colored green to red, red over 100%), then the week as a percent of the weekly limit (`Plan.menuLabel`). The Overview and Spend tabs show a session's cost against the limits (`Plan.limitShare`), and the Overview's subagent table has a column for each (`Plan.limitParts`): percent of a day (1/7 of the weekly limit, not today's allowance, so a past session's number stays the same) and of the week. Small values keep decimals (`Format.smallPercent`), because one subagent is often under 1% of the week. Update the price table when models or prices change (source: the claude-api skill's model table and `shared/model-migration.md`).
- The app finds the CLI at `CCOP_CLI`, then `CCOP.app/Contents/Helpers/ccop`, then `target/release/ccop` above the executable (for `swift run`). The CLI is in `Helpers`, not `MacOS`: `ccop` and `CCOP` are the same name on a case-insensitive file system.

### Reports and help for agents

An agent reads short reports, because every byte goes into its context and each call makes the model read that context again. `anatomy --json` of a long session is megabytes; `brief` is about 2 KB.

- `libs/core/src/rollup.rs`: `Rollup::of` turns a `Session` and its `Anatomy` into rows; `merge` adds sessions up. `rows(What, By)` is `ccop top`, `brief()` is `ccop brief`, `cause_report` is `ccop cause`. A session counts as a whole if it was active in the period, so a total can be more than `ccop usage` for the same days. `apps/cli/src/anatomy.rs` `rollup` reads the sessions on up to 8 threads: 410 sessions in about 0.6 s. With no period, reports cover 7 days.
- `libs/core/src/timing.rs`: `ccop time`. The clock is split so the parts add up: main lane's model call, then main lane's tool, then a subagent running, then nothing (a person). Time per tool or program is the union of intervals per lane (`clock_ms`), because calls sent together overlap: 970 `Edit` calls were 45 min this way and 7.5 h as a plain sum (`ToolStat.total_ms`, which the app shows). Model time includes API retries; the transcript cannot tell them apart.
- `apps/cli/src/report.rs`: the text of those reports. Every report ends with the next commands.
- `libs/core/src/guide.md`: the instructions for agents, printed by `ccop guide`, at most 3 KB (`GUIDE_MAX_BYTES`, tested). A test checks that each `ccop X` in it is a real command. Change it when a command changes.
- Nothing goes into `CLAUDE.md` or a skill on purpose: that would cost every session. A person gives the guide to one agent: Copy for Agent in a session row's right-click menu or at the end of the Overview (`AgentPrompt`), the button on the help page (the guide without a session), or "run `ccop guide`".
- Help: `libs/core/src/help.md` (with the guide as its last section); the hidden `ccop help-page` makes HTML; `build-app.sh` writes it to `Contents/Resources/help.html`; the menu's Help opens it in the browser. A test checks that the page names every visible command.
- Install Command Line Tool (`CCOPKit/CLIInstaller.swift`) links `~/.local/bin/ccop` into the bundle. A release and a dev build use the same name: the guide says `ccop` for both, and the last install wins. It checks the PATH of the login shell: an app opened from Finder has a shorter one.

### Release and updates

Same scripts and updater as `../localcron` (renamed `lr_` → `cc_`).

- Version: `[workspace.package] version` in `Cargo.toml` only. `scripts/release-lib.sh` holds the bundle id (`dev.ccop.app`), the repo (`shchahrykovich/ccop`) and the signing helpers.
- `build-app.sh --developer-id` signs `Helpers/ccop`, then the bundle, with the hardened runtime. `release.sh` bumps the version and makes `dist/ccop-<version>.dmg`; `--notarize` runs `notarize.sh` (sign the DMG, `notarytool submit --wait`, staple). `publish.sh` adds `gh release create` and checks the uploaded size. `.env.notarize` holds the notary credentials; it is git-ignored.
- `CCOPKit/Updater.swift` reads `releases/latest`, takes the first `.dmg` asset (https GitHub hosts only), and on Install: download, `spctl --assess` the DMG, then a detached bash script waits for the app to quit, mounts the DMG, checks `CCOP.app` with `codesign --verify` and the same Team ID, swaps the bundle and opens it. Log: `~/Library/Logs/ccop/update-*.log`.
- A build with no Team ID (ad-hoc: `swift run`, `install.sh`) never updates itself (`Updater.disabledReason`), so a build from source is not replaced by the release. `build-app.sh` names an ad-hoc build "CCOP Dev" (bundle id `dev.ccop.app.dev`, a slate icon with a yellow DEV band, `make-icon.swift ... dev`, and a dark menu bar battery), so it is never taken for a release and both can be installed; it has its own settings. `install.sh` removes an older ad-hoc `CCOP.app` in the same folder, never a signed one.
- `AppModel` checks 30 s after launch, then every 6 h, while the `autoUpdate` default is on (right-click menu toggle). An automatic check only reports an available update; it never installs without a click.

### Changing the JSON

The `Session`, `Anatomy` and `ccop usage` JSON exist twice: Rust (`libs/core/src/session.rs`, `anatomy.rs`) and Swift (`apps/menubar/Sources/CCOPKit/Session.swift`, `Anatomy.swift`, `Plan.swift`; snake_case keys are converted, and a digit part is capitalized: `cache_write_1h_tokens` decodes into `cacheWrite1HTokens`). Update both. `api/sessions.example.json` is hand-written and checked to have exactly the Rust fields; `api/anatomy.example.json` is written by `libs/core/tests/api_example.rs` from the real code (`UPDATE_EXAMPLES=1`). `SessionContractTests` and `AnatomyContractTests` decode both in Swift.

### Context parts are estimated

A call's context size is exact (input + cache write + cache read). The split is not: `context.rs` gives the growth between two calls first to the previous answer's `output_tokens` ("Claude output"), then to the prompts, tool results and subagent reports between them by bytes; growth with none of them is "Other"; the first call is "Start"; after a compaction "Start" + "Compacted summary"; a shrink scales every part. Claude Code's `api-request` / `api-request-blob` / `api-request-shape` records look like they hold the exact request, but most message hashes have no blob in the file (answers and tool results are not stored as blobs), so the request cannot be rebuilt from them.

## Transcript format (checked 2026-11-02; not a stable public API)

- Main file `~/.claude/projects/<folder>/<session-id>.jsonl`; subagents in `<folder>/<session-id>/subagents/agent-*.jsonl`. `<folder>` is the cwd with every non-alphanumeric character replaced by `-`; many names start with `-`, so pass `--` to `ls`. `CLAUDE_CONFIG_DIR` moves `~/.claude`; `CCOP_PROJECTS_DIR` overrides the folder for ccop.
- Tokens are in `assistant` records at `.message.usage` (`input_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`, `output_tokens`). One API answer is written as several lines (one per content block), each with the same `.message.id`, `requestId` and full usage: count it once. In 18,541 answers checked, the lines of one answer were always next to each other, which is what lets `Transcript` dedupe with only the last answer's key. Model `<synthetic>` costs nothing.
- Titles: `agent-name` (`agentName`, set by the user) wins over `ai-title` (`aiTitle`, newest wins), then the first prompt. `relocated` (`relocatedCwd`) moves the folder; `continued-in` (`continuedInSessionId`) links the next session. User records with `isMeta`, `isSidechain` or `isCompactSummary`, and tool results, are not prompts.
- Tool descriptions: `api-request-shape` records (`.shape.tools[]`: `name`, `description`, `input_schema`) hold the tools of a request, MCP tools too once they are loaded. Checked 2026-11-07 on 300 files: of 708 MCP tools called per session, 675 had a description in the session's files. `LaneReader` keeps the first paragraph, at most 300 characters, and `build` puts it on the `Cause` (`description`).
- MCP servers: `attachment` records with `attachment.type: mcp_instructions_delta` have `addedNames` and `addedBlocks` (`## <name>\n<the server's instructions>`). A name becomes the tool name's part when every character other than a letter, a digit, `_` or `-` is `_` (`claude.ai Kola` → `claude_ai_Kola`). Checked 2026-11-07 on 300 files: 92 of 117 session and server pairs had a record (Playwright has none). The text is for the model, so its first sentence does not always say what the server is; `server_description` skips only a warning and a line with no spaces.
- Subagent reports: a background subagent's report comes back as a `user` record with `isMeta: true` whose text has `<agent-message from="<agent id>">`, a frame that ends in "The report follows:", then the report with each line indented by two spaces. A `SendMessage` from another session has the same tag. `agent_message` in `anatomy.rs` makes it an event of kind `report` (`agent_id` is the sender, the part `Subagent reports`, the cause `Subagent reports`; `ccop cause ID reports`). Checked 2026-11-07 on 686 files: before, these were 87% of the context part `Other`.
- Tool calls: `tool_use` blocks in answers (`id`, `name`, `input`); results: `tool_result` blocks in the next user record (`tool_use_id`, `is_error`, `content`), with `toolUseResult` beside. An `Agent` result has `toolUseResult.agentId`; background agents return at once (`status: async_launched`), so a subagent's start and end come from its own file. `agent-<id>.meta.json` has `agentType`, `description`, `toolUseId`. `system` records with `subtype: compact_boundary` have `compactMetadata` (`trigger`, `preTokens`, `postTokens`, `durationMs`); `subtype: api_error` is an API error. The model call that writes a compaction's summary is not in the transcript: in the 3 compactions checked on 2026-11-07 there was no `assistant` record during `durationMs`, so no ccop cost includes that call.
- `fork` subagents (`agentType: "fork"` in the meta file): the file starts with a copy of the parent's history, up to the message with the call that started the fork (`toolUseId`). `ForkCopy` in `transcript.rs` forgets those lines, in the index and in the anatomy; both read the meta file for it. The line after that call holds the call's result and the fork's task, after `</fork-boilerplate>`; it is the lane's first prompt. Checked 2026-11-04 on 99 fork files: all 706 answers up to the call were also in another file of the session, none of the 2293 after it. A file without that call counts as a whole.
- Size on this Mac: about 14 GB in 7,000+ files. A first scan takes about 3 s; a scan with the index about 50-80 ms. `sessions --json` for all sessions is about 8 MB, and the app decodes it in about 160 ms.
